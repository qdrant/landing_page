Focus Rerankers on Judgment Calls

Much of what a reranker does is sorting current, in-stock, in-policy results first. The query can carry that sorting, and the model keeps the judgment calls.

  • Sort exact from similar. Put prices, versions, locations, and stock in payload filters.
  • Make a tuned query the bar to beat. Tune fusion first, and keep a reranker only if its gain holds up on held-out queries.
  • Try a planned model as a formula or a rescoring vector first.

Put the Best Fit First Across Keyword and Vector Matches

A recruiter searches "senior Rust engineer, Berlin." Keyword search knows Rust is a language, vectors know a systems programmer fits, and merge code decides who wins.

Ship Each A/B Test as a Formula Change

A returning shopper wears a size 38 and buys the same two brands every season. Merchandising wants to test how much each signal counts.

Merchandising's boosts and the weights that data scientists learn from clicks sit in the same formula, so every promotion still fits the shopper's search.

Write a formula query that boosts payload matches, reads stored scores like popularity, and decays by recency. Hold the price range with payload filters, and scale each weight to the fused score.

Bring Rare Sizes and Cross-Language Names Up to Page One

A marketplace wants rare sizes on page one. An analyst types a company's German name and expects the English record.

Data scientists bring the embeddings, and app engineers bring the trading names, so the analyst's research agent gets the English record first.

Store each representation as a named vector, prefetch each one filtered and unfiltered, then rescore with a stronger vector or a multivector. For the analyst, BM25 scores each trading name in a list, and Qdrant ranks the record by its best match.

Serve Exact Answers from Regulated Data

Back to the clinician: for a pediatric dose, a close-enough vector is a risk every reviewer rejects.

Compliance signs off on the clinician's results, and finance signs off on the RAM bill.

Keep vectors in float32 and place each in a memory tier: RAM for the prefetch, disk for rescoring. Where policy allows, add a quantized copy and rescore against the originals. Measure first reads from disk against your p99.

Bayer Keeps quantized vectors in RAM and originals on disk across about 135 million points, then rescores with 3x oversampling. Read the Bayer case study

Find Your Pattern by Experiment

Plan three to five days (a coding agent can run the loop for you).

  1. Write targets down first, such as 99% recall at p99 under 100 ms.
  2. Sample 100,000 to 1,000,000 points with labeled queries, so search runs through the HNSW index.
  3. Start with dense search, then add BM25 and fusion.
  4. Add filters and tune weights, then try a formula or a reranker.
  5. Validate on held-out queries.
  6. Load-test at peak query rate with bfb.

Make Each Gain Hold on Your Data

  • Expect recall@10 of 0.85 to 0.95 against the source.
  • Keyword relevance and facet counts that match today's, with facets exact through the exact parameter.
  • Recall under several strict filters at once, and a cluster sized with a solutions architect.
